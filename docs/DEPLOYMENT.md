# 精简部署与数据迁移

只需上传生成的 `vehicle-site` 部署目录，不需要上传外层车型 Word 文件夹、源代码、测试文件或图片归档。服务器需要 Node.js 24.15 或更高版本，以及可持久保存文件的磁盘。

## 在 Windows 本机打开精简包

不要直接双击 `dist/index.html`：网站包含数据库和管理接口，不能当作离线 HTML 使用，也不能只把 `dist/` 上传到静态网页空间。

1. 安装 Node.js 24.15 或更高版本，保留默认的 npm 安装选项。
2. 在精简包的 `vehicle-site` 文件夹双击 `启动网站.cmd`。首次使用会联网执行 `npm ci --omit=dev`，随后自动打开浏览器。
3. 本机地址为 `http://127.0.0.1:3001/`，后台为 `http://127.0.0.1:3001/admin`。关闭命令窗口或浏览器不影响服务；双击 `停止网站.cmd` 才会停止。

若提示 3001 端口被另一份网站占用，先在原网站文件夹双击 `停止网站.cmd`，再启动当前这份。不同文件夹中的数据库各自独立，修改不会互相同步；日常维护请固定使用同一份目录。重复点击同一份启动入口会打开已运行的网站。

精简包自带已构建的页面，启动脚本只安装运行依赖，无需源码、Vite 或重新构建。本机启动入口仅用于本机 HTTP 访问；服务器对外上线请按下面的“正式环境”配置 HTTPS 和常驻进程。

## 生成部署包

在开发项目目录执行：

```powershell
npm ci
npm run package:deploy
```

脚本会先运行正式构建，然后生成 `deployment/<UTC时间戳-随机编号>/vehicle-site/`。每次使用新目录，不覆盖旧包。该目录可以直接上传，也可以自行压缩后上传。成功目录包含 `PACKAGE-MANIFEST.json`；带 `PACKAGE-INCOMPLETE.txt` 的目录表示打包失败，不能用于部署。

包内包含构建后的 `dist/`、服务器 `server/`、`package.json`、`package-lock.json`、默认 favicon，以及当前所有车型（包括下架车型）和公司图标实际引用的图片。没有引用的图片不会带入。`dist/` 仅包含前端代码，图片由 `public/` 提供，不重复保存两份。

如果已有 `data/catalog.sqlite`，脚本使用 Node 的 SQLite `backup()` 创建一致性副本，保留实际车型、上下架状态、网站设置和管理员账号。副本中的登录会话、未保存上传登记和待清理媒体队列会被清空；未保存且未被业务记录引用的图片不进入包。即使源库正在使用 WAL，也不会直接复制主数据库文件。原数据库和原会话不修改。包中不再带旧的车型种子文件，避免已删除的历史车型或图片被重新导入。

如果没有数据库，包中包含 `data/vehicles.json` 和它引用的图片，供第一次启动初始化。打包期间请暂停后台编辑和图片删除；数据库有一致性快照，图片属于独立文件，若引用文件被同时删除，打包会明确失败。

部署包可能包含管理员密码哈希、公司联系方式和业务数据，是私有交付物。不要提交到公开 GitHub 仓库或公开网盘。`PACKAGE-MANIFEST.json` 记录文件大小及 SHA-256，便于核对迁移完整性。

## 首次启动与管理员初始化

进入上传后的 `vehicle-site` 目录，安装运行依赖即可，不需要在服务器重新构建：

```powershell
npm ci --omit=dev
node server/index.mjs
```

默认只监听 `127.0.0.1:3001`。打开本机 `http://127.0.0.1:3001/admin`。如果数据库没有管理员，先在此创建账号。初始密码和后续新密码需为 12–128 个 Unicode 字符，同时包含文字和数字；中文与空格可用，无需特殊符号，不允许控制字符。没有公开默认密码。已有管理员的迁移包可直接使用原账号登录，既有密码仍兼容；旧会话已清空，需要重新登录。

登录后可在后台修改密码，需验证当前密码，新密码不能与当前密码相同。修改成功会退出所有已登录设备，需使用新密码重新登录。

推荐在原电脑完成管理员初始化后再打包。也可以先在服务器本机、尚未启用生产模式时初始化；远程服务器可用 SSH 隧道将本机端口转发到服务器 `127.0.0.1:3001`。不要为了初始化而公开暴露未配置的后台。生产模式禁止创建第一个管理员。

## 正式环境

在部署目录新建私有 `.env`，把域名改为实际 HTTPS 地址：

```dotenv
NODE_ENV=production
HOST=127.0.0.1
PORT=3001
PUBLIC_ORIGIN=https://cars.example.com
COOKIE_SECURE=true
```

然后启动：

```powershell
node --env-file=.env server/index.mjs
```

`.env` 不会自动加载，需使用上面的 `--env-file`，或由进程管理器注入这些环境变量。`PUBLIC_ORIGIN` 必须与用户实际访问的完整来源一致，包括协议和非默认端口。建议由 Nginx、Caddy 或云平台负载均衡提供 HTTPS，并将请求转发给本机端口 3001。使用系统服务或进程管理器保证异常后自动重启。若运行环境要求监听所有网卡，再设置 `HOST=0.0.0.0`。

例如，在 Nginx 已配置域名、TLS 证书与 HTTPS 的 `server` 块中添加以下代理配置；HTTP 请求应在另一个 `server` 块中重定向到 HTTPS：

```nginx
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 20m;
}
```

反向代理后的登录和保存请求仍按 `PUBLIC_ORIGIN` 校验来源，生产环境需保持 `COOKIE_SECURE=true`，并通过实际 HTTPS 域名访问。后端没有 `TRUST_PROXY` 配置，不使用 `X-Forwarded-For` 区分客户端 IP；经过同一个代理的请求可能共用后端 IP 限制。应在可信代理上另行配置按真实客户端 IP 的请求限流。

后端登录失败限制为同一连接 IP 与账号组合每 15 分钟 10 次，以及同一连接 IP 每 15 分钟合计 30 次；修改密码时，同一账号每 15 分钟最多 5 次错误旧密码。失败计数保存在 SQLite，重启不会清空。

SQLite 按单个网站实例部署，不要把同一份库放在不支持其锁机制的共享网络盘上，也不要启动多个独立副本分别写入不同的库。数据库和媒体必须在持久化磁盘上；不能依赖重启后会清空的临时文件系统。

## 必须一起保留的运营文件

| 路径 | 用途 |
| --- | --- |
| `data/catalog.sqlite` | 当前车型、设置、管理员和其他运营记录 |
| `data/catalog.sqlite-wal` / `-shm` | SQLite 运行时辅助文件，在线时不要单独拷贝主库作为备份 |
| `public/vehicles/` | 从资料导入且仍在使用的车型图片 |
| `public/uploads/` | 后台上传的车型图片与公司图标 |

原始导入图也可能通过后台维护被解除引用或删除，因此备份和迁移必须以当前数据库与当前媒体文件为准。不能只复制 `public/uploads/`，也不能随意用旧 `public/vehicles/` 覆盖新目录。

后续更新前端或服务器代码时，保留线上 `data/`、`public/vehicles/` 和 `public/uploads/`，再替换 `dist/`、`server/` 及依赖清单。不要用一份更早的部署包覆盖最新运营数据库。迁移整站时，停止旧实例写入，带上最新的一致性数据库备份及其全部引用媒体，验证新站后再切换流量。

需要在运行中备份时，使用 SQLite 的在线备份功能或本项目打包脚本；直接复制正在写 WAL 的 `catalog.sqlite` 可能遗漏已提交的数据。停机备份时，可以在服务完全退出后整体保存 `data/`、`public/vehicles/`、`public/uploads/`。备份恢复后同时核对车型图片和公司图标。

## Docker

源项目提供 `Dockerfile`，可构建 Node 24 运行镜像。镜像默认不包含本机运营数据库和上传目录，部署前需迁入已初始化的数据。精简部署目录面向直接运行 Node；若采用 Docker，应在源项目构建镜像，再搭配本次部署包中的数据与媒体。

容器需要持久化 `/app/data`、`/app/public/vehicles` 和 `/app/public/uploads`，并设置 `PUBLIC_ORIGIN`、`COOKIE_SECURE=true`。空目录挂载会遮住镜像里的原图，因此首次挂载前应从本次部署包完整初始化这三个目录。运行用户为 `node`，通常 UID/GID 为 1000，宿主目录需允许其读写。运行镜像和部署包都不应放入公开仓库。

## 部署后核对

访问 `/api/health` 应返回 `{"ok":true}`；打开首页检查车型数量、照片、公司图标和联系方式。登录后台确认下架车型仍可管理，并在实际域名下验证保存设置与图片上传。不要仅以首页能打开判断数据库和持久化目录已经正确迁入。
