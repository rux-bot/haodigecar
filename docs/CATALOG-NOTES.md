## 数据核对结果

- `东风6方车.docx` 与 `东风六方车.docx`：正文完全一致，11 张对应图片的 SHA-256 也完全一致，合并为 `vehicle-01`，保留两个来源文件名。
- 东风福瑞通 V8E：原文同时写“7.3 方”和“8 方”；电机峰值功率为 `110km`，最高车速为 `100/km`。冲突容积及错误单位参数暂未写入展示字段。
- 江淮蓝猫客运版：文件名写“七方”，正文标题写“六方”。网站暂用不带容积数字的名称；没有根据尺寸自行计算、补写名义容积。
- 凯马凯捷 EM6：文档文字层只有“车辆图片/车辆参数”标题；参数已人工读取文档内图片 `word/media/image6.jpeg`。其中电池为亿纬 140.15kWh，续航为 400km。
- 福田卡文乐福中 VAN、福田风景 i9+：保留多个电池/货厢版本，续航标注“按版本”，未拼成单一配置。
- 福田领航 S1：原文栏板高 400mm，照片为低栏板车，归“平板”；未归为高栏。
- 福田领航 G6：按原文“标箱”归为“厢货”，提供的照片主要展示驾驶室及底盘，最终上装形式仍应在运营中核实。
- 奇瑞江豚二号：资料内的上牌时间、里程、准新车车况与具体租购报价属于单车历史信息，未作为车型目录中的普遍承诺发布。
- 原文未注明单位的尺寸用“尺寸（原文）”保留，没有擅自追加单位。续航为资料所载值，不代表实际工况承诺。
- 没有从历史实拍照推断“现车”，没有编造租金、售价或库存。

## 文件与重建

- `data/vehicles.json`：31 款初始种子数据，包含来源文件名；网站数据库首次初始化时读取。
- `docs/extracted-sources.json`：完整段落、表格、图片来源与哈希。
- `docs/image-publication-manifest.json`：每张提取图的原始文档及图片名、源哈希、WebP哈希、发布状态和实际存放路径。未发布图片的 `url` 为 `null`；`candidateUrl` 只用于对应原始提取编号，不代表可访问资源。
- `docs/image-archive/`：重新提取时的临时目录，完成构建或清理后删除其图片副本；原图可从 Word 文档重新提取。
- `docs/extracted-sources.txt`：便于人工检索的原文摘录。
- `docs/catalog-audit.json`：按车型记录的核对备注。
- `docs/catalog-summary.json`：分类统计。
- `docs/catalog-covers.jpg`：已选封面总览；`contact-sheet-*.jpg` 为全部提取图片的检查图。
- `scripts/extract_catalog.py`：从原文档提取文本及图片。
- `scripts/build_catalog.py`：应用经过人工复核的照片顺序、分类与参数清理，生成种子数据。
- `scripts/catalog_images.py`：校验路径后删除未引用提取图和临时归档副本，验证已引用图片内容未改变。单独运行优先读取当前 SQLite 目录，没有数据库时读取种子 JSON；不修改车型数据或原始 Word。后台上传图片由服务端单独管理。

重建需 Python 与 Pillow。运行顺序为 `extract_catalog.py`、`build_catalog.py`。固定目录映射存于 `scripts/catalog-sources.json`；增删或更名来源文档时应先更新映射和整理规则，不可直接改变既有车型 ID。再次生成种子数据不会自动覆盖运行中的数据库和后台运营修改。

提取脚本先把转换图写入临时目录，生成检查图；构建脚本按复核结果复制选中图片到公开目录并清理临时副本。未选图片不会被发布。运营开始后不要用种子重建脚本覆盖实际车型，应通过后台维护。
